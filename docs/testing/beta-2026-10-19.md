# PuppetNET – systematischer Beta-Test, 19.10.2026

> 🌐 **Sprachen · Languages:** Deutsch ↓ · [English](#english)

## Urteil und Geltungsbereich

**Lokale Demo-/Export-Beta weitgehend erfolgreich; keine Live-Freigabe.** Der öffentliche
Host `https://puppetnet-web.pages.dev/` war aus dieser eingeschränkten Testumgebung nicht
abrufbar (`curl -I --max-time 20 …`: TLS-Verbindungsaufbau, Exit 35). Das beweist keinen
Ausfall. Cloudflare-Environment, Deployment-Version, Live-HTTP-Header, echte 404-Routen
und Abschaltung des alten Workers sind **nicht unabhängig bestätigt**.

Geprüft wurden der vorhandene lokale Produktions-Export `apps/web/out`, der aktuelle
Arbeitsstand auf `arena/5fb0fe0b-puppetnet` und Offline-/Mock-Verträge. Der Export wurde
im vorherigen Arbeitsschritt mit `SITE_ORIGIN=https://puppetnet-web.pages.dev` gebaut.
Das ist nicht zwingend derselbe Stand wie das derzeitige öffentliche Deployment.
Keine Änderungen an Cloudflare, keine echten Schreiboperationen in Neo4j, keine
kostenpflichtigen Dienste und kein Push/Deployment im Rahmen dieses Tests.

## Reale Browserfunktionen im Dashboard

Nach der ausschließlich temporären Selektoranpassung erfolgreich:

   ungefragten OpenStreetMap-Kachelanfragen beim Start.

8. Erzwungen fehlendes WebGL2 zeigt verständlichen Fehler; Tabelle bleibt nutzbar.

## Befunde und Priorität

### B1 – Mittel: Kosten-Audit blockiert durch neue Domain

`scripts/audit.mjs`, Register `HOST_BUDGET`: enthält weiterhin die alte Pages-Domain,
kennt aber die neue Produktionsdomain nicht. Reproduktion: `npm run audit`.
`cost/unknownHost` meldet `puppetnet-web.pages.dev` ohne dokumentiertes Free-Tier-Budget.
Kein Beleg für reale Zusatzkosten oder Sicherheitslücke. Empfehlung: neue eigene
Pages-Domain korrekt im Register dokumentieren, Audit erneut ausführen.

### B2 – Mittel: Browserakzeptanztest hat veraltete UI-Selektoren

`tests/dashboard_browser.mjs` sucht an mehreren Stellen exakt „☷ Daten“; das aktuelle
UI heißt „☷ Tabelle“. Unveränderter Test bricht deshalb vor dem Lasttest ab.
Temporäre reine Umbenennung der Selektoren lässt alle Blöcke bestehen. Empfehlung:
Test an die freigegebene UI-Beschriftung anpassen oder stabile Selektoren verwenden.
Produktquellen und Testdatei wurden in diesem Durchlauf nicht geändert.

### B3 – Offen: Legacy-Tablet-Drawer visuell nicht verifiziert

Wiederholter Screenshot-Timeout; Grundmatrix im Wiederholungslauf vollständig grün.
Empfehlung: Rail und Inspector bei 820 px auf einem normalen Browser/Gerät separat
prüfen. Bis dahin diese beiden Zustände nicht als bestanden markieren.

### B4 – Niedrig, visuelle Stichprobe: enge Legacy-Mobile-Kopfzeile

Bei 360 px wirkt die Kopfzeile mit Logo, Suche und Demo-Badge sehr gedrängt; im
Inspector-Screenshot wird der obere Bereich des Inspectors vom fixierten UI überlagert.
Automatische Funktionsassertionen bestanden, reale Touch-/Scroll-Bedienung aber nicht
vollständig beurteilt. Empfehlung: auf einem echten Smartphone nachprüfen.
Moderne Mobilseite hat eine lange vertikale Filter-vor-Graph-Anordnung, jedoch keinen
nachgewiesenen Überlauf oder Funktionsausfall.

## Nicht geprüft / keine Aussage möglich

## Findings and priority

### B1 – Medium: cost audit blocked by the new domain

`scripts/audit.mjs`, register `HOST_BUDGET`: still contains the old Pages domain
but does not know the new production domain. Reproduction: `npm run audit`.
`cost/unknownHost` reports `puppetnet-web.pages.dev` without a documented
free-tier budget. No proof of real additional costs or a security gap.
Recommendation: document the new own Pages domain correctly in the register,
run the audit again.

### B2 – Medium: browser acceptance test has outdated UI selectors

`tests/dashboard_browser.mjs` looks for exactly "☷ Daten" in several places; the
current UI says "☷ Tabelle". The unmodified test therefore aborts before the load
test. A temporary pure renaming of the selectors lets all blocks pass.
Recommendation: adapt the test to the released UI label or use stable selectors.
Product sources and the test file were not changed in this run.

### B3 – Open: legacy tablet drawers not visually verified

Repeated screenshot timeout; base matrix fully green in the repeat run.
Recommendation: check rail and inspector at 820 px separately on a normal
browser/device. Until then do not mark these two states as passed.

### B4 – Low, visual sample: tight legacy mobile header

At 360 px the header with logo, search and demo badge looks very crowded; in the
inspector screenshot the upper inspector area is overlaid by the fixed UI.
Automatic function assertions passed, but real touch/scroll operation was not
fully judged. Recommendation: re-check on a real smartphone.
The modern mobile page has a long vertical filter-before-graph arrangement, but
no proven overflow or functional failure.

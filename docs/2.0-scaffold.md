## Ownership boundaries

- **Pages Git Integration**: console regression tests, Next.js 15 build, static HTML
  deployment. No GitHub Actions deployment token is needed.
- **Workers Builds**: Worker syntax/regression tests and Worker deploy/version upload.
- **GitHub Actions**: Python tests/lint; opted-in production GLiNER and Neo4j ingestion.
  No Node setup, npm, Wrangler, frontend build or quota-consumption API call.

`cloudflare-builds.json` is the reviewable settings manifest for the dashboard. It is
not a Cloudflare API schema and is NOT automatically imported by Wrangler. Watch paths
are dashboard settings, not invented Wrangler TOML keys. Configure them on both
projects before declaring the integration complete.

## 1. Cloudflare Pages Git Integration

Connect the GitHub repository using the native Cloudflare GitHub integration. Use:

| Setting | Value |
| --- | --- |
| Root directory | `apps/web` |
| Production branch | `main` |
| Framework | Next.js static HTML export (or no preset with the custom command below) |
| Build command | `cd ../.. && npm ci --no-audit --no-fund && npm run ci:pages` |
| Output directory | `out` (relative to `apps/web`) |
| Environment | `NODE_VERSION=22`, `NEXT_TELEMETRY_DISABLED=1` |

`apps/web/wrangler.toml` identifies the Pages project and output directory. The build
command returns to the repository root to use its workspace lockfile. The final
artifact is still `apps/web/out`. Next 15 uses `output: 'export'` and `next build`;
`next export` is obsolete. No server-side Next adapter or runtime function is used.

Optional Pages environment variable: `SITE_ORIGIN=https://<your-pages-origin>`.
`npm run ci:pages` runs `scripts/emit-og-images.mjs`, then
`scripts/emit-seo-files.mjs --build-gate` before `next build`, which writes
`apps/web/public/sitemap.xml` (URLs `/`, `/dashboard/` and one `/entity/<slug>/` per
published entity) and `apps/web/public/legacy/sitemap.xml` (URL `/legacy/`), and
rewrites the `Sitemap:` line in both committed `robots.txt` files. Without `SITE_ORIGIN`
the build ships the origin-free `robots.txt` files and no sitemap; an unusable value logs
a warning and the build continues, because a missing sitemap must not take a deployment
down. Both sitemaps are git-ignored: a committed sitemap would have to guess a hostname.
Publication itself is a separate step: `npm run emit:entities -- --input <graph.json>`
writes `apps/web/public/data/entities.json` (git-ignored) from a graph export, and the
build falls back to the committed fictional demo dataset when it is absent. See
[entity pages](entity-pages.md) for slugs, JSON-LD, the page cap and the empty-publication
guard.

Copy the Pages watch-path include list from `cloudflare-builds.json`. The primary
scope is **`apps/web/*`**. Include the root lockfile, build command script and console
test dependencies as listed: watching ONLY the app folder would miss changes that can
break or materially alter its build. Paths are repository-relative, not `/apps/web`.
The console's live-provider regression test imports the Worker, so its source is also
an explicit Pages test dependency. Pure Python pipeline changes do not trigger Pages.

For previews choose only development/PR branches you actually need. Never provide
Neo4j credentials or production graph tokens to Pages builds/previews. Static
frontend users configure the Worker URL and read token at runtime in console settings.
The static bundle does not contain server secrets. `_headers` applies strict console
CSP only under `/legacy/*` and allows same-origin embedding into the Next shell.

Cloudflare Pages Free currently documents 500 builds/month, one concurrent build and
20 minutes/build. This is a shared service allowance to monitor, not an unlimited CI
runner. Use the Free account without paid add-ons. Native Git integration build status
and the local build gates do not prove an actual deployment before account setup.

## 2. Cloudflare Workers Builds

Create/connect the `puppetnet-edge-relay` Worker to the same repository:

| Setting | Value |
| --- | --- |
| Root directory | `apps/worker` |
| Production branch | `main` |
| Build command | `cd ../.. && npm ci --no-audit --no-fund && npm run ci:worker` |
| Production deploy command | `npm run deploy` |
| Non-production/preview command | `npm exec -- wrangler versions upload` |
| Environment | `NODE_VERSION=22` |

The production deploy command runs from `apps/worker` and picks up its local
`wrangler.toml`. Version upload must not publish development commits to production.
Use **`apps/worker/*`** plus the shared dependency/test files listed in the manifest
as include watch paths. Frontend-only edits do not trigger Worker builds.

The build gate runs `node --check`, the 39 relay/graph smoke checks and the 33 MP6
hardening checks (`tests/worker_hardening.mjs`). It does not provision a database or
change secrets. Configure the following runtime secrets separately using the dashboard
or `npm exec -w @puppetnet/worker -- wrangler secret put NAME`:

- `PROXY_AUTH_TOKEN`: long random ingestion-relay bearer token.
- `GRAPH_API_TOKEN`: independent graph-read token.
- `STATUS_TOKEN` *(optional)*: `/status` bearer; without it the dashboard accepts the
  graph or relay token.
- `NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD`: AuraDB Free credentials.
- `CF_API_TOKEN` + `CF_ACCOUNT_ID` *(optional)*: Account Analytics read, for the
  Workers-requests card on `/status`. Without them the card says `n/a`.
- `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` *(optional)*: free degradation alerts
  from the cron, throttled to one message per six hours by `alert:last_sent`.
- Set `ALLOWED_ORIGINS` to the exact Pages origin(s) you trust. Verify preview policy.

**Two KV namespaces are required** for the distributed locks, the shared rate buckets
and the health snapshot:

```bash
cd apps/worker
npx wrangler kv namespace create PUPPETNET_RATE_LIMIT   # → RATE_LIMIT_KV
npx wrangler kv namespace create PUPPETNET_RESULTS     # → RESULT_KV
# paste the ids/preview_ids into apps/worker/wrangler.toml, then deploy
```

The placeholder ids in the committed file are all zeroes on purpose: `wrangler deploy`
fails until real ids are pasted in, rather than silently degrading every cross-isolate
guarantee to isolate memory. KV Free allows 100,000 reads but only **1,000 writes** per
day; the cron and the graph bucket sync are scheduled around that number
(see [worker-hardening.md § 7](worker-hardening.md#7-free-tier-arithmetic)).

`[triggers]` deploys two cron jobs with the Worker — `0 */12 * * *` (AuraDB keep-alive
write) and `23 */3 * * *` (free-tier snapshot). Cloudflare creates them on deploy; no
dashboard step is needed, and `npx wrangler triggers list` verifies them. Workers Free
allows five per account.

Keep `GRAPH_PUBLIC_READ=false` and `STATUS_PUBLIC=false`. Keep the Cloudflare account on
Workers Free. Free's 100,000 requests/day is a platform/account allowance, not a
per-project allowance. CPU is limited to 10 ms per request and per cron invocation. The
graph API budget is a hard 25 requests/minute per caller and fleet-wide and the Worker
clamps configuration above it; the relay's own `GLOBAL_RPM` is per-isolate, not a
globally exact daily counter. There are no Queues. Respect the KV free allowances.

The technical Workers Builds pricing documentation currently lists 3,000 free build
minutes/month and one concurrent build; confirm availability in your account because
Cloudflare's general pricing page has shown inconsistent Free-plan descriptions.
Workers Builds minutes, Pages build counts and Worker request limits are different
resources, not interchangeable pools. No auto-upgrade or paid overage is required.

## 3. GitHub Actions: ingestion-pipeline.yml

Only `.github/workflows/ingestion-pipeline.yml` is active:

1. Push/PR changes affecting Python or workflow configuration run offline Python
   regression tests and Ruff on `ubuntu-latest` with Python 3.11.
2. Daily schedule (`05:17 UTC`) and manual dispatch run the same tests first.
3. Production ingestion additionally requires **all** of:
   - workflow ref `refs/heads/main`;
   - repository variable `ENABLE_INGESTION=true`;
   - schedule event, or explicit manual `run_ingestion=true`;
   - actual `NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD` secrets.
4. Install CPU-only PyTorch, then pipeline GLiNER extras. Cache downloaded model weights.
5. Run a real model preflight before fetching documents or writing to Neo4j.
6. Harvest up to 100 documents and process unstructured text with GLiNER. Write graph
   data using the existing idempotent Neo4j writer. Exit 3 is a clearly logged partial
   success, not silently identical to full success. Upload a one-day report artifact.

Relay URL/token are optional repository secrets; without them the existing direct,
robots-aware, rate-limited transport can be used. DB credentials are not given to the
untrusted PR test job. No inference API key or GPU service is used. Dry run remains
available locally but missing production credentials fail the ingestion job.

The workflow-wide `puppetnet-python-ingestion` mutex prevents overlapping ingestions;
GitHub concurrency is not FIFO, so newer pending runs may replace older pending runs.
Normal per-job timeouts (20 min tests / 45 min ingestion), document and runtime caps
remain resource/runaway guards. They are NOT artificial monthly allowance checks.
No usage API, billing permission, self-imposed 1,800-minute cap or admission script
remains. Public standard-runner usage does not consume the private 2,000-minute pool.
GitHub service/anti-abuse rules and storage limits still apply. Moving to a private
repository requires revisiting billing assumptions, not silently enabling overages.

## GLiNER implementation and limitations

- Optional extra: `pip install -e './packages/pipeline[gliner]'`.
- Actions installs CPU PyTorch first from its official CPU wheel index to avoid GPU
  runtime downloads. Model inference runs locally on the standard Linux runner.
- `NLP_BACKEND=gliner`, model `urchade/gliner_small-v2.1`, threshold `0.5`.
- Default model is English; its model card lists Apache-2.0:
  https://huggingface.co/urchade/gliner_small-v2.1 . Review licenses when changing models.
- Model weights must be downloaded from Hugging Face on a cold cache. They are not
  committed. No paid inference endpoint is called. Initial downloads need outbound
  network access and available runner disk/RAM. Cache hits are an optimization only.
- GLiNER predicts person/organization/location/aircraft/vessel spans. Existing craft
  rules, entity resolution, evidence accounting, relationship typing/confidence and
  Neo4j serialization remain in use.
- GLiNER is **not** a relation model or dependency parser. Relations use conservative
  patterns/co-occurrence with the existing confidence penalty, not invented SVO parses.
- Inputs are sentence-segmented and bounded to 400-character windows to avoid silent
  long-input model truncation; names/relations crossing a window may be missed. This
  is a known recall trade-off, not a full-quality multilingual NLP replacement.
- Explicit GLiNER model-load failure is fatal. Per-document inference failures follow
  the pipeline's existing partial-failure accounting and are reported.
- Local default remains spaCy for backward compatibility. `--doctor` honors the
  selected NLP backend. `NLP_ENABLED=false` / `--skip-nlp` still override extraction.
- No transformer quality benchmark or real-world accuracy guarantee is claimed.

## Validation and remaining operator acceptance

Offline GLiNER doubles test model-selection, span validation, inference windows,
relation confidence and fail-closed loading. Python tests assert workflow gates and
native-build settings. Pages/Worker gates can be reproduced via `npm run ci:pages`
and `npm run ci:worker`; Wrangler dry-run validates packaging without deployment.

Real model download/inference and actual Neo4j/Cloudflare integration are separate
acceptance checks. The local sandbox does not allow Hugging Face downloads, so these
must run in the opted-in workflow or an appropriately networked local environment.
No claim of live inference/deployment follows from mocked/offline tests alone.

Root compatibility symlinks retain v1 tool paths. Old docs/workflows under
`docs/legacy-*` are historical, non-executing references. The old static audit embeds
v1 layout/scheduling assumptions and is not active hybrid CI. Legacy compiled CSS is
retained; its removed Tailwind 3 generation tooling needs a supported migration before
regenerating utilities. npm overrides keep known PostCSS/source-map vulnerabilities
patched while retaining Next 15.

# PuppetNET 2.0 scaffold: migration and zero-cost operation

## Scope and branch

The full history through development commit `127ab47` was fast-forward merged into
`arena/322dea42-puppetnet`. This session cannot change branches or push to `main`.
Review and integrate this branch into `main` before relying on scheduled Actions.
No infrastructure has been provisioned and no service is claimed to be live.

Actual source now lives under `apps/web`, `apps/worker`, `packages/pipeline`.
Root symlinks deliberately preserve previous Python imports, CLI commands and the
existing regression harness. Historical docs still use those paths. Do not deploy
from the historical workflows: they are archived outside `.github/workflows`.
The historical scheduling test was archived with its workflows, replaced by active
scaffold contract tests; ingestion/NLP/network/graph/security tests remain active.

The Next frontend is a **static shell around the existing console**, not a completed
React migration. Both are served from the same origin. No database credential or
shared token is compiled into the static bundle. Configure the console's Worker
provider manually in its settings. Same-origin framing is allowed; cross-origin
framing remains blocked. The legacy console's CSP is scoped to `/legacy/*` on Pages,
so its strict script policy does not break Next's generated hydration scripts.

## Free deployment choices

### Cloudflare Pages (recommended for this scaffold)

- Use a **Free** account; do not enable paid Workers or purchase add-ons.
- Project root: repository root; build: `npm ci && npm run build`.
- Output directory: `apps/web/out`; Node 22; `NEXT_TELEMETRY_DISABLED=1`.
- Deploy static assets only. There are no Next API routes, SSR or image-optimizer
  functions. `_headers` ships with the output.
- Optional CLI upload: `npm exec -w @puppetnet/worker -- wrangler pages deploy ../web/out --project-name=puppetnet`.
  This requires an existing Pages project and a Cloudflare token; it is not run by CI.

### Vercel Hobby

- Import the monorepo with root directory `apps/web`, Next.js preset.
- Workspace install uses the repository lockfile; build `npm run build`, output `out`.
- `apps/web/vercel.json` declares static output and basic security headers.
- Hobby is only an option where its eligibility and non-commercial usage terms fit.
  It must not be represented as a free commercial-hosting entitlement.
- No paid plan, cron service, observability add-on or runtime function is needed.

### Worker

```sh
npm ci
npm exec -w @puppetnet/worker -- wrangler login
npm exec -w @puppetnet/worker -- wrangler secret put PROXY_AUTH_TOKEN --config wrangler.toml
npm exec -w @puppetnet/worker -- wrangler secret put GRAPH_API_TOKEN --config wrangler.toml
npm exec -w @puppetnet/worker -- wrangler secret put NEO4J_URI --config wrangler.toml
npm exec -w @puppetnet/worker -- wrangler secret put NEO4J_USERNAME --config wrangler.toml
npm exec -w @puppetnet/worker -- wrangler secret put NEO4J_PASSWORD --config wrangler.toml
npm run deploy -w @puppetnet/worker
```

Set `ALLOWED_ORIGINS` to the exact deployed frontend origin and verify CORS with it.
Use long random independent relay and graph tokens. Never enable public reads by
accident. Credentials are Wrangler secrets, not frontend environment variables.
`workers_dev=true` makes the deployment reachable without buying a domain.

The Workers **Free account's platform quota**, not an isolate-local counter, enforces
100,000 requests/day. `GLOBAL_RPM=30` is only a per-isolate safety mechanism; it is
**not a globally exact daily quota**. Other Workers in the account share its allowance.
Do not upgrade the account to metered Workers Paid to bypass exhaustion. Exhaustion
must result in refusal, not billable overages. CPU is configured at 10 ms/request.
There are no enabled Queues bindings. Without KV the relay uses bounded in-isolate
state and direct client fallback; distributed rate limits are approximate.

Optional KV Free setup (not needed for baseline):

```sh
npm exec -w @puppetnet/worker -- wrangler kv namespace create RATE_LIMIT_KV --config wrangler.toml
```

Copy the returned ID into `CF_KV_NAMESPACE` for your deployment records and add:

```toml
[[kv_namespaces]]
binding = "RATE_LIMIT_KV"
id = "YOUR_REAL_NAMESPACE_ID"
```

to `apps/worker/wrangler.toml`. Wrangler does not interpolate `CF_KV_NAMESPACE`
automatically. Review KV write/read limits before enabling it. No namespace ID or
Cloudflare credential is committed. Queued asynchronous fetching is not part of the
zero-binding scaffold; the client can fall back to its direct rate-limited path.

### Neo4j and Telegram

Create AuraDB **Free**, not a trial of a paid instance. Configure its TLS URI and
credentials in repository secrets for ingestion and Wrangler secrets for reads.
The graph caps are guardrails, not a substitute for monitoring the actual account.
Telegram is optional. `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_IDS` are documented but
no Telegram job is scheduled in the scaffold. The existing CLI remains available.
No paid API key is required; active ingestion selects only Wikidata/news sources.
No transformer model is downloaded in CI. NLP can use its existing degraded fallback.

## Actions budget and mutex

Only two workflows are active. Both use Ubuntu, one job, and the exact same
`puppetnet-free-tier` concurrency group; CI and ingestion cannot overlap. This also
avoids graph writes competing with CI. GitHub concurrency is not a FIFO queue:
multiple pending runs may replace each other. This is deliberate load shedding.

- CI: one Python version (3.11), Node 22, at most **20 min/run**.
- Daily ingestion: opt-in repository variable `ENABLE_FREE_INGEST=true`, at most
  **10 min/run**, 100 documents, 300-second pipeline budget, no heavy analytics.
- No hourly/weekly deep harvest, screenshots, automatic deployment or additional
  maintenance schedule. Archived workflows never execute.
- A conservative admission check uses read-only Actions API access before installs.
  Every run in the repository this UTC month reserves 20 minutes, even a shorter,
  failed, old or refused run. Above 90 runs / 1,800 reserved minutes it refuses
  further useful work. API failure also refuses work. This leaves 200 minutes
  against the requested 2,000-minute planning ceiling.
- Example full 31-day month: 31 ingests × 10 + 50 CI runs × 20 = **1,310 minutes**.
  Admission reserves 81 × 20 = 1,620 minutes, so this fits conservatively.
- Reruns, fork PRs, other workflows and other repositories can consume extra minutes.
  The API guard counts runs, not account billing; it cannot impose an account-wide
  hard spending limit. Even rejected runs consume checkout/startup time, and
  arbitrary repeated triggers can exhaust the 200-minute reserve.

**Required account-side protection:** set the Actions spending limit/budget to zero
with stop-usage enabled where the account supports it; do not authorize overages.
Confirm the actual plan includes the requested 2,000 private-repository Linux minutes.
Public-repository allowances differ. Disable optional schedules if the account's
remaining quota is low. Hosting/provider terms and quotas may change; this repository
cannot guarantee lifetime free service or silently enforce another account's billing.

Artifacts are limited to ingestion reports, retained for one day. Keep their aggregate
size below the account's free storage quota; disable uploads if that is not possible.
Dependency caches also consume storage; inspect account usage periodically.

## Verification and remaining acceptance

Local verification must include the Next static build, Wrangler dry-run, active
scaffold tests, existing Worker/console smoke tests, Python suite and Ruff. Live
acceptance still requires operator accounts/secrets, deployment, CORS, a real Free
AuraDB write/read and a quota review. GitHub CI is only verified remotely after push.
The old custom static audit embeds v1 schedule/layout assumptions and is retained as
historical tooling; do not interpret its output as a v2 certification. It is not run
by v2 CI. Its security-sensitive behaviours remain covered by runtime regressions;
a complete rewrite of that audit for the monorepo is a follow-up task.

### Dependency hygiene

Next 15 is pinned to 15.5.28. Patched PostCSS/source-map-js overrides avoid known
transitive advisories while retaining Next 15. Wrangler requires Node 22. The old
Tailwind 3 generator was removed from active dependencies/scripts because its legacy
glob tooling has an unpatched high-severity advisory. The console's already compiled
CSS and licenses remain versioned; v2's shell uses plain CSS. Updating the old console's
utility classes requires a separate supported CSS-toolchain migration, not reinstalling
the archived build configuration into production CI. `npm audit` is an additional
point-in-time check, not a guarantee against future vulnerabilities.
